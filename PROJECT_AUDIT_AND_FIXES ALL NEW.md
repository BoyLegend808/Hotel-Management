## PROJECT OVERVIEW

### What It Is

- Hotel Management System called "Lumina Hospitality"
- Express.js backend running on Node.js
- HTML/CSS/JavaScript frontend (no framework)
- JSON file-based database (`db.json`)
- Partially converted from an older "Evergreen Estates" care management system

### Tech Stack

- **Backend:** Express.js, Node.js
- **Frontend:** HTML5, CSS3 (Tailwind), Vanilla JavaScript
- **Database:** JSON (db.json) with async file I/O

### CRITICAL #3: DATABASE NOT SCALABLE FOR PRODUCTION

**Severity:** CRITICAL - Blocks multi-user testing, production deployment

**Problem:**

- Using JSON file (`db.json`) as database
- Entire DB loaded into memory on every request
- No concurrent write protection (potential data corruption with simultaneous writes)
- No transactions (if payment starts, and server crashes, data is inconsistent)
- No query optimization
- Not suitable for production

**Current Behavior:**

```js
// backend/db-optimized.js
async function readDB() {
  const data = await fs.promises.readFile(DB_PATH, "utf8");
  return JSON.parse(data); // ENTIRE DB in memory
}

async function writeDB(db) {
  await fs.promises.writeFile(DB_PATH, JSON.stringify(db, null, 2));
  // No lock, concurrent writes overwrite each other
}
```

**What Needs to Happen (Priority Order):**

1. **Short term (demo):** Add file locking to prevent concurrent writes
   - Use `proper-lockfile` or similar
2. **Medium term (pre-production):** Migrate to SQLite
   - SQLite is single-file, no server needed
   - Has transaction support
   - Handles concurrent reads fine
3. **Production:** Migrate to PostgreSQL or MongoDB
   - Full transaction support
   - Indexing for performance
   - Clustering for scalability

**Quick Mitigation (Today):**

- Install `proper-lockfile` package
- Add file locking to `readDB()` and `writeDB()`
- Add transaction patterns to critical operations (booking creation)

**Files to Update:**

- `backend/db-optimized.js` (add locking)
- `backend/routes/bookings.js` (add transaction-like patterns)
- `backend/routes/payments.js` (add transaction patterns)
- `package.json` (add `proper-lockfile`)

**Time Estimate:** 4-6 hours (locking), 2-3 days (SQLite migration)

## BACKEND ISSUES

### ISSUE #4: SESSION MANAGEMENT - In-Memory Storage

**Severity:** HIGH - Not suitable for production/clustering

**Problem:**

- Sessions stored in JavaScript `Map()` in memory
- Lost on every server restart
- No way to invalidate sessions from other server instances
- 24-hour hardcoded TTL

**Current Code (backend/auth.js):**

```js
const sessions = new Map(); // IN MEMORY - LOST ON RESTART

function createSession(user) {
  const token = crypto.randomBytes(32).toString("hex");
  const session = {
    token,
    role: user.role,
    name: user.name,
    id: user.id,
    createdAt: Date.now(),
    expiresAt: Date.now() + SESSION_TTL_MS, // 24 hours hardcoded
  };
  sessions.set(token, session);
  return session;
}
```

**What Needs to Happen:**

1. Move to persistent storage (Redis or SQLite)
2. Make TTL configurable per environment
3. Add session invalidation endpoint
4. Track session activity (last access time)
5. Implement refresh tokens (short-lived access + long-lived refresh)

**Recommended Fix:**

- Use Redis for sessions (scale horizontally)
- Or use SQLite table if Redis not available
- Implement refresh token flow:
  - Access token: 15 minutes
  - Refresh token: 7 days

**Files to Update:**

- `backend/auth.js` (session storage logic)
- `backend/.env.config.js` (configurable TTL)
- `package.json` (add redis or sqlite3)

**Time Estimate:** 3-4 hours

## CODE QUALITY ISSUES

### QUALITY #1: No Module System / Global Scope Pollution

**Severity:** MEDIUM - Maintenance nightmare

**Problem:**

- All JavaScript is global scope (no modules)
- Functions/variables can conflict
- Hard to test
- Hard to reuse

**What Needs:**

1. Use ES6 modules (`.mjs` or `type: "module"` in package.json)
2. Or: Use IIFE pattern to namespace each file
3. Or: Use a bundler (Webpack already in use but not for frontend JS)

**Recommended:**

- Convert to ES6 modules + Webpack
- Or: Use IIFE pattern for now (quick fix)

**Example (IIFE Pattern):**

```js
// BEFORE
function showToast() { ... }
window.showToast = showToast; // Global pollution

// AFTER
(function() {
  function showToast() { ... }
  window.UI = window.UI || {};
  window.UI.showToast = showToast;
})();
```

### QUALITY #3: No Error Handling in Event Listeners

**Severity:** MEDIUM - Silent failures

**Problem:**

- Event listeners don't have try-catch
- Network errors silently fail
- User sees nothing when something goes wrong

**What Needs:**

1. Wrap all async operations in try-catch
2. Show error toasts to user
3. Log errors to console/logging service

**Example:**

```js
// BEFORE
button.addEventListener("click", async () => {
  const res = await fetch("/api/rooms");
  const data = res.json();
  // No error handling - if fetch fails, silent failure
});

// AFTER
button.addEventListener("click", async () => {
  try {
    const res = await fetch("/api/rooms");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const data = await res.json();
  } catch (err) {
    console.error("Failed to load rooms:", err);
    UI.showToast("Failed to load rooms. Please try again.", "error");
  }
});
```

**Files to Update:**

- All page-specific JS files
- `js/ui-utils.js` (enhance error handling)

**Time Estimate:** 2-3 hours

## PERFORMANCE ISSUES

### PERF #1: Multiple Stylesheets and Fonts

**Severity:** MEDIUM - Network requests, render blocking

**Problem:**

- 5 CSS files loaded on every page:
  1. lumina-design-system.css
  2. global-nav.css
  3. global-footer.css
  4. hotel-utils.css (should be removed after Tailwind built)
  5. ui-utils.css
  6. page-specific CSS
- 3 font requests (Google Fonts):
  1. Playfair Display (serif, headlines)
  2. Inter (sans-serif, body)
  3. Material Symbols Outlined (icons)

**What Needs:**

1. Combine non-critical CSS into single file
2. Inline critical CSS in `<head>` (above-the-fold styles)
3. Load non-critical CSS async
4. Self-host fonts (don't rely on Google)
5. Use font-display: swap or font-display: optional

**Example:**

```html
<!-- BEFORE -->
<link
  href="https://fonts.googleapis.com/css2?family=Inter:wght@400;700&display=swap"
  rel="stylesheet"
/>
<link href="/css/lumina-design-system.css" rel="stylesheet" />
<link href="/css/global-nav.css" rel="stylesheet" />

<!-- AFTER -->
<link rel="preload" as="font" href="/fonts/Inter-400.woff2" crossorigin />
<link rel="preload" as="font" href="/fonts/Inter-700.woff2" crossorigin />
<style>
  /* Critical CSS inline */
</style>
<link rel="stylesheet" href="/css/main.min.css" />
<link
  rel="stylesheet"
  href="/css/non-critical.min.css"
  media="print"
  onload="this.media='all'"
/>
```

**Time Estimate:** 2-3 hours
